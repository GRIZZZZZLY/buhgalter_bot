# Продуктовая стратегия: от записной книжки к финансовому ассистенту

**Дата:** 2026-03-15
**Scope:** Новые фичи, автоматизация, персонализация, напоминания

---

## Диагноз: почему сейчас бот — «записная книжка»

Текущий бот умеет ровно одно: записать и показать. Пользователь говорит «купил продукты на 750» — бот записывает. Пользователь спрашивает `/summary` — бот показывает. Нет причины открывать бота каждый день, если ты ничего не потратил. Нет причины возвращаться, если бот не даёт ничего нового.

Ключевая проблема: бот реактивный, а не проактивный. Он ждёт, пока пользователь что-то сделает. Продукт, которым хочется пользоваться каждый день, сам приходит к пользователю.

## Текущий функционал (инвентаризация)

### Команды
- `/start` — приветствие + кнопка WebApp
- `/summary [period]` — баланс, доход, расход, топ-3 категории
- `/delete` — удаление из последних 5 транзакций
- `/deleteall` — удаление всех данных

### Ввод текстом
- 15 паттернов распознавания на русском языке
- 28 глаголов расхода, 18 глаголов дохода
- 20 категорий (14 расход, 5 доход, 1 общая) с ~150 синонимами
- Интерактивное разрешение неизвестных категорий (fuzzy matching)
- Распознавание 8 магазинов (хардкод)

### Ввод голосом
- Whisper STT (faster-whisper / whisper-cpp)
- Постобработка: нормализация магазинов, сленга, числительных
- Мульти-парсинг: разбиение на сегменты по союзам
- Подтверждение / отмена / редактирование

### WebApp (React)
- Дашборд: баланс, транзакции, аналитика (Recharts)
- Редактирование и удаление транзакций
- Переключение периодов (today/week/month/all)

### Чего НЕТ
- Модели пользователя (нет таблицы users)
- Бюджетов и лимитов
- Повторяющихся транзакций
- Напоминаний и уведомлений
- Обучаемой категоризации (per-user)
- Ввода даты в прошлом
- Экспорта данных
- Целей накоплений
- Аналитики и трендов
- Undo последней записи
- Редактирования из Telegram

## Уровень 0 — Фундамент

### 0.1. Модель пользователя

Таблица `users`:
```
id, telegram_user_id, display_name, timezone (default Europe/Moscow),
currency (default RUB), budget_amount, budget_start_day (default 1),
reminder_morning (time|null), reminder_evening (time|null),
streak_days, last_active_at, created_at
```

### 0.2. Пользовательские маппинги категорий

Таблица `user_category_mappings`:
```
user_id, merchant_text, category, usage_count
```

Второй раз бот уже не спрашивает — он запомнил.

## Уровень 1 — Ежедневная привычка (P0)

### 1.1. Утренний брифинг

Каждое утро в настроенное время:
```
Доброе утро!
Дневной бюджет: 1,240 руб
Месяц: потрачено 62% бюджета, прошло 58% времени — в плане!
Серия: 12 дней подряд
```

Формула дневного бюджета: (месячный_бюджет - уже_потрачено) / оставшиеся_дни

### 1.2. Вечерний чек-ин

Если сегодня ничего не записано:
```
Сегодня пока ничего не записано. Забыли что-то?
[Топ-1 категория] [Топ-2] [Топ-3] [Не тратил]
```

Умное молчание: если 3+ расхода уже записано — не отправлять. Если игнорирует 3 вечера — снизить частоту.

### 1.3. Серия (Streak)

Поле streak_days в users. Показывать в утреннем брифинге. При потере — мотивирующее сообщение.

## Уровень 2 — Осмысленность данных (P1)

### 2.1. Бюджеты по категориям

Таблица `category_budgets`:
```
user_id, category, amount, period (monthly)
```

Визуализация прогресс-барами в Telegram. Алерт при превышении — мгновенно после записи.

### 2.2. «Aha-момент» — Итоги первой недели

Через 7 дней после первой записи — автоматический анализ:
- Топ категорий с процентами
- Средний чек по категориям
- Проекция мелких расходов на год
- Конкретная рекомендация по экономии

### 2.3. Еженедельный дайджест (воскресенье)

Потрачено за неделю, сравнение с прошлой, рост/снижение по категориям, самый большой расход.

---

## Уровень 3 — Автоматизация (P1-P2)

### 3.1. Повторяющиеся транзакции

Таблица `recurring_transactions`:
```
user_id, title, amount, type, category, frequency (daily/weekly/monthly),
day_of_month, next_run_at, is_active
```

Автозапись + напоминание за день. Кнопки: подтвердить / изменить сумму / пропустить.

### 3.2. Обучаемая категоризация

Per-user маппинги merchant -> category. После 5 использований — молчаливая запись без подтверждения.

### 3.3. Ввод даты в прошлом

Распознавание в парсере: вчера, позавчера, в понедельник, DD.MM, DD месяц.

---

## Уровень 4 — Умный ассистент (P2-P3)

### 4.1. Детекция аномалий

Если категория на 50%+ выше среднего за 3 месяца — уведомление.

### 4.2. «Кофе-индекс»

Агрегация мелких повторяющихся расходов с проекцией на год. Показывать раз в неделю.

### 4.3. Финансовый балл (0-100)

Компоненты: бюджет (adherence), регулярность (tracking), сбережения (savings rate). Месячное сравнение.

### 4.4. Цели накоплений

Таблица `savings_goals`:
```
user_id, title, target_amount, current_amount, deadline, is_active
```

Прогресс-бар + расчёт необходимой ежемесячной суммы.

---

## Уровень 5 — Полировка UX

### 5.1. Быстрые кнопки после записи

После каждой записи: [Ещё расход] [Отменить] [Изменить]
Кнопка «Отменить» — мгновенный undo.

### 5.2. Редактирование из Telegram

Команда /edit или inline-кнопки на последних транзакциях.

### 5.3. Экспорт данных

/export month -> CSV-файл в чат.

## Главный принцип

Бот должен приходить к пользователю, а не ждать, пока пользователь придёт к боту.

Утренний брифинг, вечерний чек-ин, алерты бюджетов, еженедельный дайджест, напоминания о повторяющихся платежах — всё это исходящие сообщения. Именно они превращают записную книжку в ассистента.
