## 1. Восстановленный текущий воркфлоу

### 1.1. Точки входа

| Точка входа | Описание |
|---|---|
| `/start` | Приветствие + примеры + inline-меню (+ кнопка WebApp, если настроена) |
| `/menu` | Текст «Выбери раздел или напиши расход/доход:» + inline-меню |
| Свободный текст | Парсинг как транзакция / вопрос советнику |
| Голосовое сообщение | STT → парсинг → подтверждение |
| Системные напоминания | Утренний брифинг, вечерний чек-ин, плановые напоминания |

### 1.2. Сценарий: Текстовый ввод транзакции (основной)

| Шаг | Действие пользователя | Ответ бота | Кнопки | Состояние чата |
|-----|----------------------|-----------|--------|---------------|
| 1 | Пишет «500 еда» | Парсит текст | — | Сообщение пользователя в чате |
| 2a (high confidence) | — | `✅ ↘ Расход 500 ₽ — Еда\nБаланс за месяц: +X ₽` | `[↩️ Отменить] [✏️ Категория]` (auto-remove через 30с) | Подтверждение + кнопки (кнопки исчезнут) |
| 2b (medium — неизв. категория) | — | `Категория «X» не найдена. Похожие: ...` | `[🍽 Еда] [🚌 Транспорт]` + `[➕ Создать «X»]` + `[❌ Отмена]` | Сообщение с выбором категории |
| 2c (low confidence — только сумма) | — | `Нашёл сумму X ₽ — это расход или доход?` | `[↘ Расход] [↗ Доход]` + `[❌ Отмена]` | Сообщение с выбором типа |
| 2d (вопрос / advisor) | — | Ответ советника | `[🧠 Продолжить в советнике]` + `[📊 Сводка] [≡ Меню]` | Ответ + навигация |
| 2e (fallback) | — | `Не понял. Попробуй так: ...` | `[≡ Меню]` | Подсказка |
| 3 (после 2b) | Нажимает категорию | Сохраняет + `✅ ...` | `[≡ Меню]` | Исходное сообщение редактируется |
| 3 (после 2c) | Нажимает тип | Показывает категории | Сетка категорий + `[❌ Отмена]` | Исходное сообщение редактируется |
| 4 (после 3 → тип) | Нажимает категорию | `✅ ...` сохранено | `[≡ Меню]` | Исходное сообщение редактируется |

**Дополнительно после сохранения:**
- Если превышен бюджет категории → бот отправляет **отдельное** сообщение-алерт
- Может отправить real-time insight (макс 1 раз в день) — **отдельное** сообщение

### 1.4. Сценарий: Inline-навигация (Меню)

| Шаг | Действие пользователя | Ответ бота | Кнопки | Состояние чата |
|-----|----------------------|-----------|--------|---------------|
| 1 | `/menu` или нажимает `≡ Меню` | «Выбери раздел или напиши расход/доход:» | `[📊 Сводка]` / `[📋 Запланированные] [🔄 Регулярные]` / `[💰 Бюджеты] [🧠 Советник]` / `[⚙️ Настройки] [ℹ️ Помощь]` | Одно сообщение (edit если из кнопки, reply если из команды) |

**Навигация по разделам** — при нажатии кнопки сообщение **редактируется** (edit_message_text). Если edit невозможен (например, сообщение слишком старое), отправляется **новое** сообщение. Это ключевой принцип: навигация через inline-меню переиспользует одно сообщение.

#### 1.4.1. Раздел «Сводка» (nav:stats)

Показывает баланс, доходы/расходы, топ категорий за выбранный период.

Кнопки: `[Сег] [Нед] [Мес ✓] [Всё]` + `[📋 Операции] [≡ Меню]`

#### 1.4.2. Раздел «Операции» (nav:ops)

Список последних 10 транзакций с суммами и категориями.

Кнопки: `[Сег] [Нед] [Мес ✓] [Всё]` + `[🗑 Удалить] [📊 Сводка] [≡ Меню]`

В режиме удаления (nav:ops:delete_mode) — список транзакций-кнопок для удаления + `[← Назад] [≡ Меню]`.

#### 1.4.3. Раздел «Запланированные» (nav:planned_list)

Список запланированных расходов (просроченные + ближайшие).

Кнопки на экране списка: `[➕ Добавить] [← Назад] [≡ Меню]`

#### 1.4.4. Раздел «Регулярные» (nav:recurring_list)

Список активных правил.

Кнопки на экране списка: `[➕ Добавить] [← Назад] [≡ Меню]`

#### 1.4.5. Раздел «Бюджеты» (nav:budgets)

Отчёт по бюджету: общий + покатегорийный.

Кнопки: `[✏️ Общий бюджет] [🗂 По категории]` + `[≡ Меню]`

#### 1.4.6. Раздел «Настройки» (nav:settings)

Текущие настройки + навигация.

Кнопки: `[📅 Начало периода]` + `[🔔 Напоминания]` + `[🌍 Часовой пояс]` + `[← Назад]`

#### 1.4.7. Раздел «Помощь» (nav:help)

Экран с примерами ввода и списком команд.

Кнопки: `[← Назад]`

#### 1.4.8. Раздел «Советник» (nav:advisor)

Онбординг → режим диалога (текст/голос) → ответы с кнопкой `[✕ Завершить]`.
Таймаут 10 минут неактивности.

### 1.5. Сценарий: Запланированные расходы (planned_input)

| Шаг | Действие пользователя | Ответ бота | Кнопки | Состояние чата |
|-----|----------------------|-----------|--------|---------------|
| 1 | Нажимает `📋 Запланированные` в меню | «Опиши запланированный расход — название, сумму и дату...» | `[📋 Мои запланированные] [← Назад]` | Редактируется в навигационном сообщении |
| 2 | Пишет «маникюр 2100 15 апреля» | LLM разбирает → «Запланировал:\n🏷 маникюр\n💰 2,100 ₽\n📅 2026-04-15\n🗂 Красота» | `[✅ Сохранить] [❌ Отмена]` | **Новое** сообщение (reply_text) |
| 3a (Сохранить) | Нажимает ✅ | «✅ Запланировано: маникюр — 2,100 ₽ на 2026-04-15» | `[≡ Меню]` (в main_menu_inline_keyboard) | Сообщение редактируется |
| 3b (Отмена) | Нажимает ❌ | «Отменено.» | inline-меню | Сообщение редактируется |

**Важно:** после шага 2 `mode` очищается — следующее текстовое сообщение уже будет обычной транзакцией, а не продолжением planned input.

### 1.6. Сценарий: Регулярные транзакции (recurring_input)

Аналогичен planned_input:
1. Вход из меню → описание + `[🔄 Мои регулярные] [← Назад]`
2. Свободный текст → LLM парсит → подтверждение с `[✅ Сохранить] [❌ Отмена]`
3. Подтверждение → «✅ Добавлено» + inline-меню

### 1.7. Сценарий: Управление бюджетом (budget)

#### Через навигацию (inline):

2b. `budget:pick_category` → сетка категорий → выбор → mode `budget_category_input` → ввод суммы → подтверждение

### 1.9. Сценарий: Удаление (/delete, /deleteall)

**Одиночное удаление:**
1. `/delete` → список транзакций-кнопок
2. Нажимает кнопку → `✅ Удалил запись.` + `[≡ Меню]`

**Удаление всего:**
1. `/deleteall` → «Это удалит все записи. Точно?» + `[Да, удалить всё] [Отмена]`
2. Подтверждение → `✅ Удалено записей: N.` / `Отмена — записи не тронуты.`

### 1.10. Сценарий: Настройки (settings)

Для каждого параметра одинаковый паттерн:
1. Нажимает кнопку настройки → сообщение редактируется с инструкцией + `[❌ Отмена]`
2. Пользователь пишет значение → бот валидирует и подтверждает
3. Результат: «✅ ...» + `[← Назад] [≡ Меню]` (done_keyboard)

**Подразделы напоминаний:**
- `[⏰ Утреннее] [🌙 Вечернее]` + `[❌ Выключить все]` + `[← Назад]`

### 1.11. Сценарий: Категории (nav:categories)

1. Экран со списком: каждая строка `[🍽 Еда] [✏️] [🗑]` (🗑 только для пользовательских)
2. Нажатие ✏️ → экран редактирования: `[✏️ Изменить название] [🎨 Изменить emoji] [🙈 Скрыть]` + `[🗑 Удалить]` (если custom) + `[← Назад]`
3. Изменение — бот просит ввести текст → подтверждает

**Добавление:**
1. `➕ Добавить` → «Введи название» → ввод текста
2. «Теперь отправь emoji» → ввод emoji
3. «Выбери тип» → `[💸 Расход] [💰 Доход] [↔️ Оба]`
4. Подтверждение

**Удаление с переназначением:**
1. Если есть транзакции → показывает сетку категорий для переназначения
2. Если нет → удаляет напрямую

## 2. Проверка понимания сценария

### Уверенно восстановлено:
- Полная цепочка текстового ввода: парсинг → high/medium/low confidence → сохранение + undo
- Голосовой ввод: placeholder → STT → подтверждение → confirm/edit/cancel
- Inline-навигация: edit_message_text с fallback на send_message
- Все input-режимы: planned_input, recurring_input, budget_total_input, budget_category_input, advisor
- Undo: 30-секундное окно с auto-remove кнопок
- Catfix: пост-save коррекция категории
- Полный flow настроек, категорий, удаления, экспорта
- Evening check-in с быстрым вводом суммы

### Неоднозначности:
1. **saved_actions_keyboard vs undo_inline_keyboard** — при high-confidence текстовом сохранении используется `saved_actions_keyboard` (с `↩️ Отменить` + `✏️ Категория`), а при voice confirm — `undo_inline_keyboard` (только `↩ Отменить`). Непоследовательно.
2. **Двойное сообщение при lowconf** — после `lowconf:cat` выбора: сначала `edit_message_text` с результатом, затем `_send_saved_with_undo` — **два сообщения** (одно с `[≡ Меню]`, другое с `[↩ Отменить]`).
3. **Аналогично catres** — после выбора категории: `edit_message_text` + `_send_saved_with_undo` — тоже два сообщения.
4. **Voice edit** — после `voice:edit` бот отправляет промпт, но следующее сообщение пользователя попадает в обычный text_message_handler, а не в специальный voice-edit handler. Voice edit mode хранится в pending store с TTL 10 минут.
5. **Mode lifecycle** — mode очищается сразу после обработки в planned/recurring input. Но в nav_callback тоже очищается. Нет проблемы с «застрявшим» mode?
6. **Budget free-form flow** — `budget:set_total` и `budget:set_category` устанавливают mode, но **я не нашёл** соответствующий callback handler для budget в прочитанном коде. Это может означать, что код для `budget_callback_handler` находится в непрочитанной части или что flow неполный.

### Предположения:
- Budget callback handler (`budget:*`) зарегистрирован и обрабатывает `budget:set_total`, `budget:pick_category`, `budget:total_confirm`, `budget:total_cancel`, `budget:set_category:*`, `budget:cat_confirm`, `budget:cat_cancel`.
- Утренний брифинг — формат не исследован, предполагаю простое текстовое сообщение без inline-кнопок.

## 3. Основные UX-проблемы текущего флоу

### 3.1. Дублирование сообщений при низкой уверенности

**Проблема:** В `catres_callback_handler` и `lowconf_callback_handler` после выбора категории бот:
1. Редактирует исходное сообщение (`edit_message_text`) с результатом
2. Отправляет **новое** сообщение через `_send_saved_with_undo`

Результат: **два сообщения** с одинаковым текстом подтверждения.

**Влияние:** Захламление чата, путаница пользователя.

### 3.2. Непоследовательность пост-save кнопок

**Проблема:**
- Текстовый ввод (high confidence) → `saved_actions_keyboard`: `[↩️ Отменить] [✏️ Категория]`
- Голосовой confirm → `undo_inline_keyboard`: только `[↩ Отменить]`
- Lowconf/catres → `done_keyboard` + отдельное undo-сообщение

**Влияние:** Пользователь не знает, чего ожидать после сохранения. Возможность исправить категорию доступна не всегда.

### 3.3. Mode очищается после первого сообщения в planned/recurring input

**Проблема:** Если LLM не смог разобрать текст (ошибка), mode уже очищен. Следующая попытка пользователя будет обработана как обычная транзакция.

**Влияние:** Пользователь вынужден заново заходить в режим planned/recurring через меню.

### 3.4. Шум от служебных сообщений

**Проблема:** Budget alert, insight, planned due reminders — все отправляются как отдельные сообщения без контекста навигации.

**Влияние:** В истории чата накапливаются разрозненные сообщения.

### 3.5. Отсутствие «Категории» в главном меню

**Проблема:** В `main_menu_inline_keyboard` нет кнопки «Категории» — попасть можно только через `nav:categories` (который вызывается из навигации, но не из главного меню непосредственно).

**Влияние:** Раздел «Категории» скрыт от пользователя. (Примечание: кнопка `🗂 Категории` определена как `MENU_BTN_CATEGORIES`, но **не используется** в `main_menu_inline_keyboard()`.)

### 3.6. Нет визуальной иерархии в меню

**Проблема:** 6 кнопок в меню без чёткой приоритизации. Сводка — самое частое действие — выглядит так же, как Помощь.

### 3.7. Inconsistency в формате подтверждения

**Проблема:**
- `format_saved` → `✅ ↘ Расход 500 ₽ — Еда` (parse_mode=HTML)
- `format_voice_saved` → тот же формат, но отдельный метод
- Плановые: `✅ Запланировано: маникюр — 2,100 ₽ на 2026-04-15`
- Recurring: `✅ Добавлено: аренда −30,000 ₽ — каждый месяц, 1-го`

Разный стиль подтверждений.

## 4. Анализ inline-кнопок

### 4.1. Что работает хорошо

| Элемент | Почему удачно |
|---------|--------------|
| `[✅ Да] [✏️ Изменить] [❌ Отмена]` (voice) | Чёткие 3 варианта, понятная иерархия: подтвердить / исправить / отменить |
| Period tabs `[Сег] [Нед] [Мес ✓] [Всё]` | Компактные, с индикатором текущего выбора |
| Auto-remove undo через 30с | Убирает шум, но даёт время передумать |
| `[← Назад] [≡ Меню]` | Консистентная навигация |

### 4.2. Что неудобно

| Проблема | Пример | Рекомендация |
|----------|--------|-------------|
| **Слишком много кнопок в одной клавиатуре** | `edit_categories_keyboard` — до 18+ кнопок (все категории по 2 в ряд) + back | Показывать только релевантные категории (по типу транзакции), или группировать |
| **Нет визуального разделения действий** | `planned_manage_keyboard`: `[✅ Учесть] [✏️ Учесть с другой суммой]` / `[📅 Изменить дату] [🗑 Удалить]` | «Удалить» визуально не отделён от позитивных действий |
| **Длинные подписи кнопок** | `✏️ Изменить сумму и учесть` (30+ символов) | Сократить до `✏️ Другая сумма` |
| **Неочевидные иконки** | `↕️ Тип` (edit) — не интуитивно | `🔄 Тип` или `↕️ Расход⇄Доход` |
| **Кнопка `categories:noop`** | В списке категорий кнопка с названием категории ничего не делает (noop) | Убрать кнопку-noop или сделать её действие — открытие редактирования |
| **`❌ Отмена` vs `❌ Отменить` vs `Отмена`** | Три разных формулировки для одного действия | Унифицировать: `❌ Отмена` везде |
| **`🗑 Удалить` в edit рядом с `↕️ Тип`** | Деструктивное действие на одном уровне с обычными | Перенести `🗑 Удалить` в отдельную строку или добавить подтверждение |

## 5. Анализ сообщений в чате

### 5.1. Классификация сообщений

#### Точно должны оставаться:
| Сообщение | Причина |
|-----------|---------|
| `✅ ↘ Расход 500 ₽ — Еда` (подтверждение сохранения) | Основной результат — пользователь видит историю |
| `↩ Отменено.` | Пользователь должен видеть, что отмена прошла |
| `✅ Запланировано: ...` | Подтверждение создания |
| `✅ Добавлено: ...` (recurring) | Подтверждение создания |
| Budget alert | Важное уведомление |
| Planned due reminder | Пользователь должен действовать |

#### Лучше редактировать (вместо отправки нового):
| Сообщение | Текущее поведение | Рекомендация |
|-----------|-------------------|-------------|
| Навигация (Сводка, Операции, ...) | Уже редактируется ✅ | — |
| Подтверждение planned/recurring input | reply_text → edit_message_text конфирмации | Редактировать confirmation-сообщение |
| Budget alert после сохранения | Отдельное новое сообщение | Встроить в сообщение подтверждения |
| Settings подтверждение | Новое сообщение | Можно объединить с экраном настроек |

#### Лучше удалять после взаимодействия:
| Сообщение | Почему |
|-----------|--------|
| `🎤 Обрабатываю голосовое…` (placeholder) | Уже удаляется ✅ |
| `🤔 Анализирую…` (ask_command) | **НЕ удаляется** — остаётся в чате навсегда |
| Промежуточные инструкции («Введи новую сумму...») | После ввода уже не нужны |

#### Служебные / временные:
| Сообщение | Рекомендация |
|-----------|-------------|
| Fallback: «Не понял. Попробуй так:» | Оставлять, но стоит добавить кнопку `[≡ Меню]` — уже есть ✅ |
| «❌ Не смог разобрать. Попробуй ещё раз.» | Оставлять, но добавить `[🔄 Попробовать снова]` (возврат в mode) |
| Insight (realtime) | Отдельное сообщение — нормально, т.к. это полезный контент |
| Suggestion keyboard (/improve_categories) | Каждое suggestion — отдельное сообщение. Для 5+ предложений = спам |

## 7. Предлагаемый улучшенный вариант сценария

### 7.1. Текстовый ввод (улучшенный)

```
Пользователь: «500 еда»
Бот: ✅ ↘ Расход 500 ₽ — Еда
     Баланс: +12,500 ₽
     ⚠️ Еда: 8,500/10,000 ₽ (85%)     ← budget alert встроен
     [↩ Отменить] [✏️ Категория]        ← 30с auto-remove
```

Вместо двух сообщений (подтверждение + alert) — одно интегрированное.

### 7.2. Low confidence (улучшенный)

```
Пользователь: «750»
Бот: Нашёл сумму 750 ₽ — это расход или доход?
     [↘ Расход] [↗ Доход]
     [❌ Отмена]

Пользователь: нажимает [↘ Расход]
Бот: ↘ Расход 750 ₽ — выбери категорию:     ← edit того же сообщения
     [🍽 Еда] [🚌 Транспорт]
     [🏠 Жильё] [💊 Здоровье]
     ...
     [❌ Отмена]

Пользователь: нажимает [🍽 Еда]
Бот: ✅ ↘ Расход 750 ₽ — Еда               ← edit того же сообщения
     Баланс: +11,750 ₽
     [↩ Отменить] [✏️ Категория]            ← auto-remove 30с
```

Всё в одном сообщении — ноль мусора.

### 7.3. Planned input (улучшенный)

```
Меню → [📋 Запланированные]
Бот: Опиши расход — название, сумму и дату.    ← edit nav-сообщения
     [📋 Мои запланированные] [← Назад]

Пользователь: «маникюр 2100 15 апреля»
Бот: Запланировал:                              ← новое сообщение
     🏷 маникюр · 💰 2,100 ₽ · 📅 15.04 · 🗂 Красота
     [✅ Сохранить] [❌ Отмена]

Пользователь: [✅ Сохранить]
Бот: ✅ Запланировано: маникюр — 2,100 ₽ на 15.04  ← edit
     [📋 Ещё один] [≡ Меню]                         ← возможность добавить ещё
```

**Ключевое:** после ошибки LLM → mode НЕ сбрасывается → пользователь может попробовать ещё раз.

### 7.4. Vечерний check-in (улучшенный)

```
Бот: 🌙 Вечерний чек-ин
     Что потратил сегодня?
     [🍽 Еда] [🚌 Транспорт] [🎬 Развлечения]
     [✅ Ничего не тратил]

Пользователь: [🍽 Еда]
Бот: 🍽 Еда — сколько?                     ← edit
     [100₽] [200₽] [500₽]
     [1000₽] [2000₽]
     [✏️ Другая сумма]

Пользователь: [500₽]
Бот: ✅ ↘ Расход 500 ₽ — Еда               ← edit (а не новое + edit!)
     [🍽 Ещё расход] [✅ Готово]             ← возможность записать несколько
```
